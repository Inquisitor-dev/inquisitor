# backend/CLAUDE.md

Backend-specific guidance (NestJS 11 + Prisma). The root `CLAUDE.md` holds the project overview, the basic commands and the rules that hold everywhere (the answer never reaches the client, ids, copy, test mode, the `npm run lint --fix` warning). The reasons behind many rules here, and trial results, are in `docs/tasarim-gerekceleri.md`, `docs/v3-persona-tasarimi.md` and `docs/hikaye-hakemi.md`.

## Commands (details)

- `npm run stories:generate -- --per-bucket N [--universe a,b] [--difficulty a,b] [--max-tokens N] [--dry-run]` — fill the story pool: each story is generated the way the game does (`generateStoryPackage`), checked by `validateStoryPackage`, reviewed by the judge and saved to `Story` as `DRAFT` (or `REJECTED` when validation fails or the judge finds a certain error), with the validation, judge result and token cost in `reviewResults` (`StoryReviewRecord`, `stories/story-generation.ts`). Buckets (universe × difficulty) are filled round-robin and existing non-rejected stories of the current rule version count, so a stopped run resumes; it stops at the token budget or after 3 failures in a row. An invalid number (`--per-bucket 0`) stops the command instead of falling back to the default. Needs the local DB with the `Story` table (`npm run prisma:push`); `--dry-run` needs no DB.
- `npm run stories:approve -- --list [--status DRAFT|REJECTED|APPROVED|all] | --show <id> | --approve <id> [--note ..] [--force] | --reject <id> --note .. | --stats` — human approval of the story pool (`prisma/story-approve.ts`, `stories/story-approval.ts`); an 8-character id prefix is enough. A story that failed code validation can never be approved, one the judge rejected only with `--force`; a rejection needs a note. The decision (status, `--by` or `STORY_REVIEWER` or Enes, note, time) is added to `reviewResults.decision`. Only `APPROVED` stories of the current rule version (`STORY_RULE_VERSION` in `stories/story-package.ts`: 1 before v2, 2 v2, 3 with the culprit's cover story, 4 with the v3 persona plan, 5 with the wildcard list; `storyRuleVersion` sets it when a draft is saved) are picked by the game when `STORY_POOL_ENABLED=true`; older stories stay in the pool but must be regenerated.
- `npm run stories:export` / `npm run stories:import -- [--dry-run]` — the story pool is shared through the repo: every story is one JSON file in `backend/stories/<universe>/<difficulty>/<id>.json` (`prisma/story-sync.ts`, `stories/story-files.ts`). Whoever generates and approves exports and commits; everyone else (and the live DB, with its `DATABASE_URL`) imports after pulling. Stories match by id; nothing is deleted on either side, and a local record newer than its file (a decision not exported yet) is never overwritten.
- `npm run stories:review -- --fixtures | --generate N | --sessions N | --stories a,b` — run the story reviewer on its fixture set, freshly generated cases, local DB cases or pool stories (re-judged next to their stored verdict, the record is not changed) with real Gemini (`prisma/story-review.ts`, `docs/hikaye-hakemi.md`); token usage goes to its report, not the DB.
- `npm run usage:report [days]` — LLM token averages per kind and totals per case.
- `npm run abilities:scan-eval` — measures Çelişki Taraması with real Gemini (`prisma/contradiction-eval.ts`).
- Service specs build services with mocked Prisma/LLM objects; see `game-sessions.service.spec.ts`.

## Modules (`backend/src`)

- **Request validation:** a global `ValidationPipe` (`main.ts`, `whitelist: true`, `transform: true`) validates bodies against the `class-validator` DTOs in each module's `dto/` folder (`*/dto/*.dto.ts`) and silently drops undeclared fields. A new body field must be declared in its DTO, or it never reaches the controller; new endpoints should take a DTO instead of an inline body type. Board and notebook routes read `@Body('board')` / `@Body('notebook')` directly. `auth/current-user.decorator.ts` provides the authenticated user.
- A global `ThrottlerGuard` limits every route to 20 req/min.

### `auth/`
Email verification-code signup (mails via `MAIL_USER`/`MAIL_PASS`), password login and JWT (`JwtAuthGuard`).
- Also owns daily quota tracking (`checkAndResetDailyQuota`, session/message counters on `User`) and per-user audio settings.
- The admin user is bootstrapped from `ADMIN_EMAIL`/`ADMIN_PASSWORD` in `onModuleInit`.
- `JWT_SECRET` is mandatory (`jwt-secret.ts`, no fallback).
- `send-code` rejects every already-verified account, including the admin.
- The verification code is never returned in the API response. Only when `ALLOW_TEST_MODE=true` and the email fails is it included in the message, so local signup works without SMTP.

### `game-sessions/`
Session lifecycle: create, advance time of day / end day, notes, search warrants, condemn, timeout, and `GET /game-sessions/:id/evidence` (the evidence log).
- The daily session quota is enforced in the **controller**. Universe and difficulty are not gated server-side yet (they will be tied to market purchases).
- Every route resolves the session with `findOwnedSession` (`session-access.ts`); other users' sessions return 404.
- `toPublicSession` (see the root rule) also adds `crimeScene: { id, appearance }` (`MESSY`/`TIDY`, null for older cases), so the client can pick the scene's picture; the player sees both at the crime scene anyway. It also adds `lastDay`, today's `closedToday` and `detention` (below).
- **Per-session state** lives on `GameSession` (day, `timeOfDay` 0–4, warrants, `locationClues` JSON, `truthReveal`, `caseFacts`, `notes`), `SessionNpcState` (`currentFear`, lie tendency, `dynamicPrompt`, `shownEvidenceIds`) and `Evidence` (`kind` CLUE/VERIFICATION/CONFESSION, `category` ITEM/STATEMENT, unique per session+kind+source). A case lasts 4 days. Creating a session marks the user's previous `ACTIVE` sessions as `LOST`.
- **Evidence split:** `ITEM` evidence (physical objects found at locations) is shown in the inventory as polaroid photos; `STATEMENT` evidence (confessions, testimony) appears in the notebook as a record card on the day it was obtained; it is no longer appended to `GameSession.notes`.
- **`GameSession.notes`** is the free-text "quick notes" (Hızlı Notlar). The crime-scene page sidebar and interior clue snippets still write to it, and the notebook shows it on its first spread.
- **Verdict report (Hüküm Dosyası)** (`game-sessions/verdict/verdict-report.ts`): `POST /game-sessions/:id/condemn` takes an optional `report` next to `npcId` (evidence ids, weapon, motive, time of death, each innocent's involvement kind, a free-text account of how it happened; `VerdictReportDto`). The culprit alone decides WON/LOST; the report is scored 0–100 in code against `caseFacts` ids (`scoreVerdict`, weights in `FIELD_WEIGHTS`; fields the case does not have are left out and the rest rescaled). Supporting evidence is what implicates the culprit or clears an innocent on the board (never a planted crime-scene trace), the body when a weapon chain exists and the last-conversation testimony. The account is graded by a Gemini judge (`llm/prompts/verdict-judge-prompt.builder.ts`, usage kind `VERDICT_JUDGE`; the player's text is treated as untrusted data; test mode uses `templateJudgement`); if the judge fails, the account is left out of the score. The result is stored on `GameSession.verdictReport` and returned as `verdict`; the reward and leaderboard points are scaled by `rewardMultiplier` (0.5–1, 1 without a report, so old clients are unaffected). `GET /game-sessions/:id/verdict-options` returns the form's choices (suspects, the universe's whole weapon list, motives, times, involvement kinds) without revealing the answer.
- **Solution paths** (`scenarios/solution-paths.ts`, texts in `game-sessions/verdict/solution-report.ts`): `GET /game-sessions/:id/solution` returns up to 3 evidence chains that solve the case, only once the session is `WON`/`LOST` (400 while `ACTIVE`). `solutionPaths` minimises the solver's solution (drops every clue it can do without, indirect ones first), then bans each clue of that path in turn to find others; paths are sorted shortest first. Every step is marked `found` from the player's `Evidence` rows (`graphClueIdsOf`; an `ALIBI` row's source is the speaker, the graph clue is the cleared suspect's). Texts come from code (names and place labels, never ids); the warrant count follows `warrantLimitOf`.

### `npcs/`
`POST /npcs/interact` (one dialogue turn), `POST /npcs/confront` (show an evidence item to an NPC, optionally with a spoken remark in `message`) and `POST /npcs/history`. `npcs.service.ts` orchestrates a turn and persists `DialogueHistory`; the LLM receives the conversation's **last** 10 messages.
- `prompt-builder.ts` (`buildNpcPrompt`): the NPC/narrator system prompt from scenario config + session state, including the confession rules, fear state and the evidence being shown.
  - Every character also gets **what everyone in town knows** (`publicCaseFacts`: the victim and that the body was found at the crime scene), so a bluff such as "the murder happened at your place" is not believed.
  - A shown evidence item comes with its origin (`describeEvidenceOrigin`: found at the crime scene / at another place / at your own place, or whose statement it is) and the player's remark, so the character does not tie it to the wrong place.
  - The NPC system prompt ends with SECURITY RULES that treat player messages as in-world speech, never as instructions.
- `warrant.ts`: **search warrants are decided by code** (`decideWarrants`). The player never asks in text: the issuer's dialogue screen has an "Arama İzni İste" window where the place is picked, sent as `warrantLocationId` on `/npcs/interact` (`InteractDto`; checked by `assertWarrantRequest` before the quota is spent: only an issuer, only a case place, never the crime scene). Issuers per universe are in `WARRANT_ISSUERS` (`warrantIssuersOf`, `isWarrantIssuer`); `GET /game-sessions/:id/warrants` returns them with the limit, the warrants left, the active and used ones. At most `MAX_WARRANTS` (2) per case, 3 with the Hevesli Kadı wildcard (`warrantLimitOf`; the solver still plans with 2). The issuer's prompt only receives the decision (granted / already held / limit reached) to voice in character; asked in words, it sends the player to the formal request and never refuses on its own. Every other character's prompt names the issuers and sends the player there (`otherWarrantLine`). Any `[GRANT_WARRANT]` tag the LLM writes is stripped and ignored.
- `evidence-recorder.ts` writes `Evidence` rows; `test-reply.builder.ts` builds test-mode replies.
- All routes check session ownership. `interact` and `confront` also require an `ACTIVE` session and spend the daily message quota; `interact` messages and confront remarks are at most 500 characters.
- An evidence item can be shown to the same character only once: `assertConfrontable` runs before the quota is spent and rejects a repeat with 400 ("Bu kanıtı ona zaten gösterdin."). The dialogue screen disables already shown items.
- Replies return `newEvidence`, `fear` (`{ level, band }`, null for narrators) and, when a statement was added, the updated `notes`.
- `evidence.ts`: the **evidence log**. The LLM appends hidden tags (`[CLUE_FOUND]` from narrators, `[EVIDENCE_REVEALED]` from the testimony witness), which are stripped server-side and turned into `Evidence` rows. Confessions (`CONFESSION`) are recorded only by code at the fear threshold; a `[CONFESSED]` tag written in conversation is ignored. `sharesTestimony` also catches a witness who tells the testimony without the tag; stems every conversation shares (`COMMON_STEMS`: gece, yarısı, birinin…) do not count (why: `docs/v3-persona-tasarimi.md` §8).
- `fear.ts`: **fear is driven by code**, see "Fear and confessions" below.
- `prompt-guard.ts` answers prompt-injection attempts in character without calling the LLM, and replaces replies that leak prompt section headers. `stripMarkdown` removes `**`, `*`, headings and code marks from replies, since the dialogue screen shows plain text. An empty model reply (usually a safety block at a breaking point) is retried once in `generateNpcResponse`; if a forced confession still comes back empty (`EMPTY_NPC_REPLY`), the reply is built from `confessionText` so the player does not see "Hmm...".
  - Its `foldTurkish` makes text matching diacritic-insensitive (names, evidence stems).
- `mentions` (`case-statements.ts`) finds a character's name at the start of a word, with any suffix ("Lin'in"), never inside a word ("bilinen" does not mention Lin Feng); titles do not count. Statement capture, the leak and trace checks and the named-evidence rule all use it.

### Fear and confessions (`npcs/fear.ts`, `prompt-builder.ts`)
- Showing evidence raises `SessionNpcState.currentFear` (own location clue +7, so it always breaks an innocent; implicating evidence +3, irrelevant or repeated 0, max 10, −1 each night). Starting fear is `startingFear(baseFear)` (0–4).
- The threshold depends on the character's `temperament` (`fearThresholdOf`: STEADY 8, NORMAL 7, FRAGILE 6, stored in `caseFacts.fearThresholds`; older cases use 7), and the fear bands shift with it. Tehdit's cap and Nabız's points-to-threshold use the same per-character threshold.
- At the threshold an innocent is forced to confess, and the confession is recorded by code (it appears in the notebook). This (or telling the secret anyway, below) is the **only** way a confession is recorded: in conversation they deny or deflect, however accurate the accusation. Threats, bargains, insults and "someone already confessed" never break anyone.
- The break prompt gives the exact text recorded in the notebook (`confessionText`), so a suspect with nothing shameful to hide (a witness, a fully innocent one) tells their plain alibi instead of inventing a crime tied to the shown evidence. A helper's or scavenger's confession also says whom they gave the weapon to or when they found the body.
- A secret told below the threshold still counts for the unwitting helper and the scavenger: if a reply overlaps enough with their hidden extra (`confessionSecret`, `revealsSecret`, names not counted), the confession is recorded as if they broke. Not for the culprit: their early "confession" would name them. Instead, until they break, the culprit's prompt holds only the first part of the cover story (where and what, `splitCover`: the first sentence, or up to the first semicolon or comma when Gemini wrote one sentence); the shameful part appears only in the break instruction. The scenario prompt asks for exactly two sentences.
- The confession rules depend on the role: a fully innocent suspect is told they have no secret at all, every innocent's only secret is the one in their role, and nobody may invent a crime, deal, meeting or detail about the victim to confess or to explain themselves.
- Shown evidence that only makes an innocent look suspicious is described as such ("may fit other people too"); shown evidence that names a character without implicating them is described as such, so they do not deny a record of their own alibi. Every character is told that fear never makes them confirm events or statements the player claims but they do not know.
- Every innocent (in their whereabouts) and the culprit (in the truth) are told the time of death from `caseFacts.timeOfDeath`, so nobody invents another hour.
- **Culprit cover story (`culpritCover`):** in v2 cases the culprit breaks at the threshold too and tells a prepared lie as their "confession": an alibi alone at their own place plus a small shameful secret that innocently explains their location clue, never the murder. It is recorded as a `CONFESSION` exactly like an innocent's (`confessionText`), so the one who never breaks no longer names the culprit. The culprit sees only the cover story's place and activity until they break (see above), gives that when asked about that night and tells the rest only when they break; they never reveal their real motive or any non-public detail of the truth, and any tension with the victim they admit is the one in the cover story. Cases without `culpritCover` (older ones and old pool stories) keep the old behaviour: the culprit only panics and never confesses.

### `board/` — the investigation board
`GET`/`PUT /game-sessions/:id/board`, `POST /game-sessions/:id/board/think`. The pure logic is in `board/domain/` (`board-judge.ts`, `board-sanitizer.ts`, `board-thought.ts`, `board.types.ts`); `board.ts` only re-exports it.
- The board (cards, positions, strings) is stored on `GameSession.boardState`. `sanitizeBoard` drops cards for evidence the player has not found or suspects not in the case, and clients can never write a string's verdict.
- String types depend on the two ends: suspect–evidence `CLEARS`/`IMPLICATES`, evidence–evidence `SUPPORTS`/`CONTRADICTS`, anything else `LINK` (not judged).
- "Düşün" (think) judges strings in code against `caseFacts` (`judgeBoard`). A string only confirms what its two cards themselves say; for example, a planted crime-scene clue is exposed only when it is linked to the verifying evidence. The judgments never name the culprit.
- A correct `IMPLICATES` string on evidence that fits several suspects (the crime-scene trace, a description witness) is marked `shared`, and the monologue says it does not rule the person out rather than that it points at them.
- The verdicts are then turned into the detective's inner monologue: Gemini writes it (`generateBoardThought`, which receives only the verdicts), test mode returns a `[Test Düşüncesi]` template.
- Thinking is allowed once per in-game day (`boardThoughtDay`); if there is nothing to judge, the day's use is not spent.
- A location clue clears its innocent owner; tied to the culprit it is judged neither way for `IMPLICATES` (it shows a motive, not guilt), so a searched place does not name the culprit in one string.
- Each think judges at most `MAX_STRINGS_PER_THOUGHT` (3) strings that have no verdict yet, oldest first (`judgePending`); judged strings keep their verdict (sealed) and the rest wait for the next think, which the monologue mentions. The limit keeps one think from testing every combination (e.g. tying the trace to every suspect) and naming the culprit.
- v2 evidence on the board: a description witness implicates everyone the description fits (never only the culprit), a partial witness clears the suspect they saw elsewhere, an `ALIBI` clears the suspect it vouches for, a confession never clears the person who confessed (the culprit's cover story is a confession too; innocents are cleared by independent evidence), a fully innocent suspect's confession clears the person they were with (mirrored in `case-graph.ts`), the helper's confession implicates the culprit, and the body supports the helper's confession. The threat letter and the raid trace are judged like the description witness.

### `personas/` + `scenarios/personas/` — killer personas and night events (v3)
Design and every decision: `docs/v3-persona-tasarimi.md`; room image prompts: `docs/ev-odalari-gorselleri.md`.
- `planPersona` (`scenarios/personas/persona-plan.ts`) runs at the end of `planCase`, after a sound plan is found (so earlier random choices keep their order), and stores `CasePlan.persona`: no persona on easy, 50% `PSYCHOPATH` on medium and hard. A persona has an action pool (`PERSONA_POOLS`), not a fixed order: each action has the nights it may happen on, 1–3 actions are drawn on separate nights (1–3; no move on the last night, also the one İkinci Nefes adds). All three Psychopath actions are enabled. The player is never told the persona.
- **`THREAT_LETTER`** (nights 1–2): Gemini writes only `threatLetter` with the scenario (one extra field); `ensureThreatLetter` (`personas/threat-letter.ts`) rejects a short letter, swearing (short words matched whole, so "sıkıntı" and "götür" pass) or any suspect's or the victim's name and falls back to the universe's own letter. The trace on the paper is chosen in code from `LETTER_TRACES` (`scenarios/personas/letter-traces.ts`: per universe, each trace tagged with the three suspects it fits, every suspect in at least two), never by Gemini. The letter lands in the inventory as `Evidence` kind `LETTER` (category `ITEM`, source `home`; photographed with the player's home). Its trace fits the culprit and two others (`traceId`, `traceFits`): the board and confront treat it like the description witness (implicates and frightens everyone it fits), and the verdict report neither counts nor penalises it.
- **`BREAK_IN`** (nights 1–2): a place is forced at night and stays closed the next day; its owner tells what happened afterwards (`breakInOwnerLines`; if it was the culprit's own place, they staged it and tell it like a victim). Break-in texts are written as "<place>: gece zorla girildi" so they work with any place name.
- **Night raid** (`personas/raid-engine.ts`, pure, 11 tests incl. 2000 random games): the player wakes in the bedroom; four rooms (bedroom, kitchen, hallway, doorstep), light, what they hold (knife, or a gun for Mavi Rozet), noise 0–3 and the attacker's room (planned as `raidStart`; Kar Kâhini sees it in a dream). Noise ≥ 2 brings the attacker one room closer; meeting them with light and a weapon (or the gun) or calling out at the right moment after listening makes them flee (GOOD: a `RAID_TRACE` from `LETTER_TRACES` fitting the culprit and two others, judged like the letter); hiding or six quiet turns is NEUTRAL; meeting them in the dark unarmed is BAD (on hard the first time is a struggle, a second ignored warning is DEATH and loses the case). Every bad end is preceded by a warning (an adjacent attacker is heard, also on waking); a locked kitchen keeps them out. Texts are ready-made per universe with explicit Turkish case forms (`personas/raid-texts.ts`), no Gemini.
  - On the raid night `endDay` starts the raid instead of closing the day (`beginRaid`), `endDay` is refused while it runs, `POST /game-sessions/:id/raid/act` plays one action and `GET /game-sessions/:id/raid` returns the view (never the attacker's room).
  - When it ends the day closes; BAD costs the next morning slice, 20% of this case's reward (`raidRewardFactor`, not the token balance) and one found item (`stolenEvidenceIds`; never the crime scene trace, the body or the bonus traces; the plan's two-path rule keeps the case solvable): it stays listed with `stolen: true` but cannot be shown, pinned or cited.
  - **Çatı Geçişi on the raid night:** the player is out, so there is no raid; the home is found searched (outcome `SEARCHED`: 10% off this case's reward, nothing stolen, the paper and an event card say so) and the day closes as usual.
- **Detention (nezaret)** (`scenarios/personas/detention.ts`, `POST /game-sessions/:id/detain`): once per case, never on the last day, only a suspect. The person's place closes for the rest of the day (`DETAINED` closure) and they are released next morning; overnight their fear rises by one instead of falling, and the next day they are resentful and curt (`detentionPromptLines`). The town hears it and the next paper reports it. If the culprit was detained, that night's move is not cancelled but shifted to the next free night inside its own window (`effectivePersonaPlan`, used by the night processing, the raid and the closures), or dropped if there is none, so "nothing happened tonight" proves little. `toPublicSession` returns `detention` (the player knows whom they detained).
- **Town events** (`scenarios/personas/town-events.ts`, planned with the persona, independent of it, about half the cases on every difficulty): a suspect is out of town for one day (day 2 or 3) with a reason from code. It is foreshadowed: the owner's prompt carries their plan in its own "YOUR SCHEDULE" section at the very end (`ownPlanLines`, in relative days: "tomorrow", "the day after tomorrow", never a day number), the others hear it as gossip (`townPromptLines`), and the paper announces it the morning before ("Yarın … kapalı") and on the day. Neither a town event nor a break-in hits the holder of the verifying evidence, and they never fall on the same day.
- **Closed places** (`closuresOn`, `scenarios/personas/closures.ts`): `toPublicSession` returns only today's `closedToday`; `NpcsController` rejects talking to the owner or searching the place before the quota is spent (`personas/closure-message.ts`).
- Story pool rule version 4 is a package whose plan has `persona` (`storyRuleVersion`); version 3 stories are no longer picked.
- **Nights** run when the day closes (`advanceDay` → `runNight`, `personas/persona-session.ts`); `processNight` (`personas/persona-night.ts`, pure) records what happened in `GameSession.personaState` (never sent with the session) and writes the next morning's paper. **A paper comes every morning**, with or without an event (so a missing paper is no clue): the first morning announces the murder, later ones carry the killer's move and ordinary town news (`personas/newspaper-texts.ts`, per universe). `GET /game-sessions/:id/newspaper` returns today's paper.
- An event is also written as `Evidence` with category and kind `EVENT` (the notebook shows it on that day's page). It is not evidence: the client store drops it, and the board, the verdict report and confront exclude it on the server.
- Everyone in town knows what happened (`publicNightLines` in the NPC prompt: everyone, the speaker included, has heard of it; nights are given relative to today ("last night", "two nights ago"), never by day number; asked what is new, a character tells the murder and the night events first and today's ordinary news only after them); only the culprit is told they did it and never to bring it up (`culpritNightLines`). Every character and the letter use the universe's title for the player (`newspaperTextsFor(...).investigator`). Trial notes: `docs/v3-persona-tasarimi.md` §8–9.

### `abilities/` — player character abilities
`GET /game-sessions/:id/abilities`, `POST /game-sessions/:id/abilities/use`. Ability texts in the frontend (`config/outfitStories.ts`) must match these server rules.
- The worn character is sent as `characterId` when a session is created, checked against `outfit_<id>` ownership (403 otherwise; default `engizitor`) and locked on `GameSession.characterId` for the whole case.
- `abilities.ts` holds the definitions and `availability` (daily / per-case / passive limits, night rules). `ability-effects.ts` holds the pure effect math. Uses and lasting effects live in `GameSession.abilityState`.
- Effects hook into existing systems: fear (Tehdit, Vizör Kilidi in `endDay`), warrants (İz Sürme skips the persuasion but counts toward the 2-warrant limit, which the case solver assumes), the quick notes (`GameSession.notes`, via `appendToNotes`: Hakkında Söylenenler (`archive_summary`, formerly Arşiv Özeti: what the other suspects told the player about one person, collected in code), Muhbir, Çelişki Taraması; Muhbir names a random unsearched place, not one it already named while others are left (`abilityState.informantNamed`), and never looks at the case facts), the NPC prompt (Sessiz Oda; the culprit is told their concrete answer is their cover story), the message quota (Sabır, in `NpcsController`), time (Kulis skips `advance-time`; Çatı Geçişi enters at night and the next day starts at `timeOfDay` 1) and the board (Veri Sızdırma, `BoardService.leakString`, spends the day's think).
- Aşama 4 yetenekleri (16 karakter, 17 yetenek): İkinci Nefes (Yeşim Hekim; `condemnNpc`'ta ilk yanlış hüküm vakayı bitirmez, kişiyi aklar ve günü kapatır, son günde vakayı uzatır, ödül/puan yarı, cevapta `culpritId` yok), Derin Tefekkür (Ak Turna; panoda günde 2 "Düşün", `abilityState.thoughts`), Rüya Tabiri (Kar Kâhini; o gün ifadesi olan herkes, doğrulayan tanık, kısmi tanık, son konuşan ve mazeret doğrulayan, sorulmasa da anlatır, `dreamDay`; anlatılacak her ifade defterdeyse hak harcanmaz, `hasUntoldStatement`), Keskin Göz (Ayaz İzcisi; arama izni olan mekânın ipucu hemen deftere, izni harcar), Teyit (Gece Muhabiri; `POST /npcs/quotes` + `/npcs/verify-quote`, bir şüphelinin gerçek sözü başkasına okunur, LLM kaydı `VERIFY_QUOTE`).
- **Vaka uzunluğu sunucuda:** `lastDayOf(abilityState)` (4, İkinci Nefes son günde kullanıldıysa 5); `toPublicSession` her cevaba `lastDay` ekler, `endDay` son günden sonrasını reddeder.
- Çelişki Taraması sends only the replies the player has heard to Gemini (`llm/prompts/contradiction-prompt.builder.ts`) and drops items whose quotes are not in those replies. It runs in two steps: the first call lists up to 5 candidates (each with its own `bothTrue` check), then `buildContradictionCheckPrompt` asks about every candidate again with the two full answers and keeps at most 3. Code also drops items whose note says there is no contradiction or whose quote claims nothing ("Hatırlamıyorum"). An unreadable reply is asked once more; a failed scan does not spend the use; its token usage is logged as `CONTRADICTION_SCAN`. It must not flag culprits more often than innocents; measured with `npm run abilities:scan-eval` (results: `docs/tasarim-gerekceleri.md`).

### `search/` — location search (hidden object)
Design and open decisions: `docs/nesne-arama-tasarimi.md`.
- A place is searched in its areas: each area is a non-NPC hotspot of the interior (`areaId` = hotspot id, e.g. tavern `barrels`, `fireplace`) with its own close-up cluttered picture. The clue lies in exactly one area: `planCase` draws it last (`withSearchAreas`, after wildcards, independent of the culprit) into `CasePlan.searchAreas`, and the scenario prompt tells the LLM to place the clue there (the scene's `clueSpot` phrase). Only that area can be searched (`openArea` in `getSearch`; `start` refuses any other); a failed search is retried in the same area with a new list. Plans without `searchAreas` (older pool stories) get an area seeded from the session id.
- A place with search scenes is searched by finding objects in the area's cluttered picture instead of talking to the narrator: first the listed objects, then the one real spot (a loose plank, a hidden compartment), which records the place's clue exactly like the narrator's `[CLUE_FOUND]` (`evidenceFromTags`; `VERIFICATION` when the verifying evidence is there) and spends the warrant. A place without a scene keeps the narrator search (mobile always uses it).
- Scenes are in `search/scenes/<universe>[-<place>].ts` (medieval: `medieval.ts` tavern, `medieval-church.ts`, `-mill`, `-graveyard`, `-farm`, `-clinic`; all gathered in `scenes/index.ts`) (`SearchSceneDef`: universe, place and `areaId`, image under `frontend/public`, objects and final spots as `[x, y, w, h]` percent boxes). `DRAFT` scenes open only in test-mode sessions; `sceneProblems` (run by the tests) checks ids, boxes, at least 10 objects and one final spot. Boxes are made with the frontend's `/dev/scene-editor`.
- `search-game.ts` is pure: the target list and the final spot are drawn with a seed (session, place, attempt), so a reload shows the same list and a new attempt a new one; list length, time limit, miss and hint penalties depend only on difficulty (`SEARCH_SETTINGS`), never on the case, so the culprit's place is searched exactly like any other.
- The state is `GameSession.searchState` (per place: `areaId`, targets, found, final spot, start time, penalties, `RUNNING`/`WON`/`FAILED`); time runs out on the server (`withExpiry`). The view sent to the client has labels and progress, never a box; every click is checked on the server; when two target boxes overlap the smaller one wins. A failed search (time out, also when misses or hints use it up) costs one time of day, once (`timeCharged`; never past night, `timeOfDay` 4; the day is only closed by the player) and can be started again with a new list. Every response carries `timeOfDay`.
- Routes (`search.controller.ts`): `GET /game-sessions/:id/search/:locationId` (`available`, `areas`, `openArea` + last view), `POST …/start` (`SearchStartDto { areaId }`), `POST …/click` (`SearchClickDto`, 120/min), `POST …/hint` (a circle around one unfound target, costs time), `GET …/test-spots` (the running attempt's boxes, test-mode sessions only, for checking the annotation), `POST …/test-solve` (test-mode sessions only). All need an `ACTIVE` session, an active warrant for the place and the place open today (`closedMessage`).

### `notebook/`
`GET`/`PUT /game-sessions/:id/notebook`, stored on `GameSession.notebookState`.
- One page spread per in-game day. Items are the player's text boxes, taped evidence photos (with a caption and a slight tilt), pen strokes and the positions of record cards, in percent of the page (`notebook.ts`).
- A pen stroke stores its color (`ink`/`red`/`blue`), size (1 thin, 2 thick) and flattened points `[x1, y1, x2, y2, ...]`. Strokes have their own limit (`MAX_STROKES` 300, `MAX_STROKE_POINTS` 120 per stroke) and do not count toward the 150-item limit.
- The notebook PUT route allows 120 requests per minute (`@Throttle`), because it autosaves while the player writes and draws. `main.ts` raises the JSON body limit to 1 MB for drawings.
- Record cards are the session's `STATEMENT` evidence (confessions, testimony); their text is never stored in the notebook, it comes from `Evidence` on every load. A card stays on the day its evidence was obtained.
- `sanitizeNotebook` drops unknown items, cards for evidence the player does not own, photos of anything but the player's own `ITEM` evidence, duplicates and empty text, and clamps positions, days, tilt and text length (600; captions 160).

### `llm/`
Single `LlmService` using the **OpenAI SDK pointed at Gemini's OpenAI-compatible endpoint** (`GEMINI_API_KEY`).
- The HTTP client lives in `llm/client/gemini-client.ts`; the prompts for scenarios, NPC replies and board thoughts are in `llm/prompts/*.builder.ts`.
- **Token usage logging:** every successful call goes through `LlmService.complete`, which logs and stores one `LlmUsage` row (`llm/usage/llm-usage.recorder.ts`: kind `SCENARIO`/`SCENARIO_REVIEW`/`CLUE_REPAIR`/`WITNESS_REPAIR`/`VERDICT_JUDGE`/`STORY_REVIEW`/`NPC_REPLY`/`CONFRONT`/`NARRATOR`/`BOARD_THOUGHT`, plus `CONTRADICTION_SCAN`/`VERIFY_QUOTE`, model, prompt/completion tokens, duration, `sessionId`). A failed write only logs a warning. `createSession` pre-generates the session id so scenario calls are tied to the case. New LLM calls must pass a usage context.
- `GeminiClient.createCompletion` walks a model fallback chain (`GEMINI_MODELS` env, comma-separated), with retries on 404/429/5xx/connection errors. If `GEMINI_MODELS` is unset, the hard-coded `DEFAULT_MODELS` list is used (`gemini-3.5-flash-lite`, `gemini-3.1-flash-lite`, `gemini-flash-latest`); Render and local `.env` set the same chain. Google retires models regularly (`gemini-1.5-*`, `gemini-pro` and `gemini-2.5-flash` already return 404), so recheck the list with `GET /v1beta/models` when replies start failing.
- Generates both NPC replies and the per-session scenario (story, truth reveal, per-NPC secret prompts, per-location clues), then runs a consistency-reconciliation pass. **Repair steps after generation** (`repair*` in `llm.service.ts`; each tries one small LLM call, then falls back to code):
  - Culprit's own location clue gives the murder away (blood or the case's weapon, `culpritClueGivesAway`) and the verifying evidence is not there → `repairCulpritClue` (`llm/prompts/clue-repair-prompt.builder.ts`) rewrites the clue and the matching truth sentences to show the motive instead; fallback: a plain motive note from code.
  - A planted trace must point at everyone it frames (by name or place, `traceMissesFramed`) → `repairPlantedTrace` rewrites the trace and the truth; fallback: code appends a mark for the missing ones.
  - A verifying witness never saw who did it: if `verificationText` or the witness's npcPrompt names the culprit (`mentions`) → `repairWitnessLeak` (`llm/prompts/witness-repair-prompt.builder.ts`, usage kind `WITNESS_REPAIR`) rewrites both to describe only the act; fallback: a plain testimony without names from code.
  - No innocent's location clue or npcPrompt may name the culprit (a sale record does not show the buyer) → `repairInnocentLeaks` rewrites every such field in one call (the unwitting helper's own prompt is exempt, since they know whom they gave the weapon to); fallback: the clue becomes a plain note from code and the sentences naming the culprit are dropped from the prompt.
  - Fully innocent partners must name the same place: if the canonical places in their two alibis (`placesIn`, character names removed first; it knows Turkish suffixes and consonant softening, "Kadim Tapınak" → "tapınağın", "Balıkçı İskelesi" → "iskelemde", and a short name like "Bar" counts only alone or with a case ending) do not overlap → `repairAlibiPlaces` rewrites the second partner's alibi and location clue to the first one's place; fallback: the first alibi is used for both. When a single fully innocent suspect's partner has another role (e.g. a scavenger), the fully innocent one is rewritten, since the partner's alibi and clue carry their own secret.
  - A partial witness saw the person at the place in that person's alibi, and the game gives the witness that place from code (`linkPromptLines`); a sentence in the witness's generated prompt that names the seen person together with a place their alibi does not name is dropped in code (`dropWrongSightings`).
  - The unwitting helper knows whom they gave the weapon to; if their generated prompt does not name the culprit, code appends it (`ensureHelperKnowsBuyer`), and the prompt never mentions confessing or breaking. Only the written record of the deal at their place leaves the name out.
  - The culprit's cover story is checked in code (`ensureCulpritCover`): if it is missing, names another suspect, mentions blood, the weapon or the crime scene, a plain lie from code replaces it.
  - Dynamic prompts never tell a character when to confess: the scenario prompt says so, and as the last repair step `removeConfessionInstructions` (`llm/prompts/confession-instructions.ts`) drops sentences that still do ("Sorguda bunu itiraf edeceksin", "sıkıştırılınca anlatırsın"; a witness who tells what they saw when asked and negatives like "söylemezsin" are kept).
  - Finally `cleanDraftIds` (`llm/prompts/internal-ids.ts`) replaces internal ids left in any generated text ("'mill' (AURA-9)", "Lin Feng ('tavern')", `crime_scene`) with the character's name or "olay yeri"; the scenario prompt also tells the LLM never to write ids or English words.

### `stories/` — the story reviewer and pool
Design and measurements: `docs/hikaye-hakemi.md`.
- `reviewStory` (`story-review.ts`) checks a pre-generated case (`StoryReviewInput`: `CaseFacts` + the LLM texts) before human approval. Code always looks for internal ids in the texts (`findInternalIds`: location ids, snake_case ids, catalog enum names, `CERTAIN`), for common words written without Turkish letters (`findMissingDiacritics`: cunku, icin, seyin…, `DOUBT`), for confession instructions left in role texts (`findConfessionInstructions`, the same rule as `removeConfessionInstructions`, `CERTAIN`) and for alibis that name another part of the night than the time of death (`findOffTimeAlibis`, `DOUBT`).
- A Gemini judge (`LlmService.reviewStory`, `llm/prompts/story-review-prompt.builder.ts`, usage kind `STORY_REVIEW`) looks for drift only reading can find: truth vs alibis and clues, roles told to confess or a helper who does not know whom they gave the weapon to, a description that points at the culprit alone, language, wound/time logic. The rules the generation repairs already fix (`repair*` in `llm.service.ts`) are on its do-not-report list, and so are the cover over the body and the weapon missing from the clues (they are case facts). A time that only says when something is planned ("sabah teslim edilecek") is not a time of the night; a partial witness's sighting is compared with that suspect's alibi (`sightings` row). The judge first fills a short worksheet (each innocent's alibi vs truthReveal, where each piece of evidence appears, instructions in roles, times, wound, language), then lists findings. Every finding quotes its field; a quote not found in that field is dropped. `TRUTH` findings are capped at `DOUBT`; an unreadable reply is asked once more, and if only the worksheet is broken the trailing `issues` list is still read.
- Code decides: any `CERTAIN` finding → `REJECT`, only `DOUBT` or no judge → `HUMAN`, none → `PASS`.
- `review-fixtures.ts` holds a clean case and copies with one known error each, used by the unit tests and for measuring the judge (`review-eval.ts`).
- `buildCaseFacts` (`game-sessions/case-facts.ts`) builds `CaseFacts` from a plan and a draft for both session creation and the review command.
- Before the judge, `validateStoryPackage` (`story-validation.ts`, no LLM) checks a `StoryPackage`: the v2 fields (`validateV2StoryPackage`), that plan, facts and texts agree (same culprit and v2 details, a role for every suspect, a clue for every place, an alibi and exactly one involvement for every innocent, the weapon in the universe's catalog, the witness description when needed), that the opening `scenario` text names neither the victim nor the culprit alone (the culprit with only some suspects is a warning), and that the plan still passes the solver (`isPlanSound`). A missing culprit cover story is a warning (that story keeps rule version 2 and is never picked). Errors reject the package; warnings go to the human reviewer.

### `scenarios/` — static game content
- Each universe (`medieval`, `modern`, `cyberpunk`, `china`, `winter`) is one file in `scenarios/universes/` holding its NPC personas, locations, localized location labels and its 5 crime scenes (`crimeScenes`, plus `crimeSceneBody`, the cover over the body), registered in `UNIVERSE_REGISTRY`.
- NPC `role`s and location `description`s are written in Turkish: they go into the scenario and NPC prompts, and Gemini copies English fragments from them into the story. `personaPrompt` stays in English, since it only describes how the character speaks.
- `getScenarioConfig(type, difficulty, crimeSceneId)`: with the case's crime scene id (`crimeSceneIdOf(caseFacts)`), the `crime_scene` location is described to the LLM as that place, with the covered body. Pass it wherever NPC or narrator prompts are built.
- `scenario-config.ts` is the facade (`getScenarioConfig`, `getLocalizedLocationLabel`, `normalizeScenarioType`). Difficulty `easy|medium|hard` picks the first 5/6/6 NPCs of the universe (`NPC_COUNT`; the 4-NPC mode was removed). Medium and hard are separated by the case settings in `case-setup.ts`: hard has one fully innocent suspect instead of two, a witness description that fits 4 suspects, planted traces 60% of the time (`PLANNED_CHANCE`) and fear thresholds one point higher (at most 8). The frontend mirrors the suspect list (`getSuspectsForScenario`) and the map's `minDifficulty` (`frontend/CLAUDE.md`).
- `clues-config.ts` holds clues tagged with the NPC ids they implicate.

## The case plan (`scenarios/case-setup.ts`)

`planCase` is called from `GameSessionsService.createSession`; the plan is stored as `GameSession.caseFacts`.
- A random culprit and a HURRIED (genuine clue) / PLANNED (planted clue) murder style.
- The crime scene (`crimeSceneId`): one of the universe's 5 places, picked last so earlier random choices keep their order. It is nobody's home or workplace and does not appear on the map. The story is written around it, and every character knows where the body was found (`publicCaseFacts`). The crime scene narrator gets the scene's appearance (`sceneState`) straight from `caseFacts`, so it matches the picture even when the generated clue leaves it out.
- An information budget: the crime-scene clue eliminates exactly `ELIMINATION_TARGET[difficulty]` suspects.
- A MESSY/TIDY scene appearance that is independent of the clue (deliberately hidden from players).
- A verifying evidence item (CORROBORATION or FLAW) placed at a location or in one NPC's testimony, an alibi for each innocent, and the victim's name and profession.
- **Vaka Motoru v2 (in progress):** the plan also holds a weapon (`case-catalog.ts` WEAPONS, only improvised ones for a hurried murder), a motive, a time of death, per-NPC fear thresholds (optional `temperament` on NPC definitions) and an `involvements` list: each innocent's link to the murder (witness, own motive, unwitting help, scavenger, last conversation, or fully innocent). Two fully innocent suspects are each other's alibi partners (never a chain); a single one gets another innocent as partner. Shared-alibi lines in NPC prompts give the partner's account as a summary to retell in their own words, never a sentence to repeat. They are stored as ids so the end-game report can be scored in code.
- A testimony witness describes the culprit by a description that fits several suspects (`witnessDescriptionFits`), never by name.
- **Solvability is checked in code before any LLM call:** `case-graph.ts` turns the plan into an evidence graph (source, prerequisites, fear pressure, eliminations) and `case-solver.ts` (`solveCase`, `criticalPoints`) simulates the player. `planCase` re-draws the details, then the base case (keeping the murder style), until the plan is solvable within 2 warrants, needs at least `MIN_WARRANTS[difficulty]` warrants and has no single critical clue (two independent paths).
- The scenario prompt (`buildCaseBrief`, `caseDetailsLines`) gives the LLM the weapon, motive, time of death, each innocent's link to the murder and, for a testimony witness, the suspects the description must fit; the LLM returns `witnessDescription` (stored in `caseFacts`). The crime scene narrator describes the wound type from the weapon's method in code, never the weapon itself.
- **Wildcards** (`scenarios/wildcards.ts`, texts in `personas/wildcard-texts.ts`, design and every decision in `docs/wildcard-tasarimi.md`): drawn last in `planCase` (`withWildcards`, after the persona and town events), stored as `CasePlan.wildcards`, at most one, in about 30% of cases, with the kinds allowed per difficulty (`WILDCARDS_BY_DIFFICULTY`). A wildcard that changes solvability goes through the solver (`graphWithWildcards`, applied by `buildCaseGraph` too; `isGraphSound`) and is dropped if it fails. All texts come from code; no Gemini.
  - `LEFT` (medium only): a suspect who is not the culprit, the holder of the verifying evidence or the owner of another closure leaves town on the morning of day 3; the solver assumes their statements, confession and place clue are gone. Paper notices the day before and on the day, the owner's `YOUR SCHEDULE` line, gossip for the others, and a `LEFT` closure from day 3 on.
  - `SHORT_DAY`: day 2 or 3 starts at `timeOfDay` 2 (`shortDayStart` in `advanceDay`); the paper announces it the day before.
  - `RUMOR`: from day 2 an unverified rumor about any suspect, the culprit included, with equal odds; an `EVENT` card (source `rumor`), the target's prompt line is the same for culprit and innocent, never board evidence.
  - `RELUCTANT`: only the testimony witness; until the crime-scene trace or the body (chosen in code) is shown to them (`shownEvidenceIds`), the testimony text is left out of their prompt (`reluctantLock`), the sentences of their generated role text that tell it are dropped too (`withoutTestimonySentences`), and it is never recorded (`verificationLocked`); when the awaited item is shown in that very reply (`reluctantOpened`) they are told this is what they were waiting for. Rüya Tabiri still makes them talk. Trial notes: `docs/wildcard-tasarimi.md`.
  - `VICTIM_NOTE`: a note in the victim's pocket, read out by the crime scene narrator and recorded with the body as `NOTE` evidence (source `victim`, text from `VICTIM_NOTES` by motive, names nobody); frightens nobody, counts as supporting evidence (motive).
  - `EXTRA_WARRANT`: a third warrant (`warrantLimitOf`), announced in the first paper.
- **v2 statements** (`npcs/case-statements.ts`): `BODY` (the wound under the cover, recorded from the crime scene narrator's `[BODY_EXAMINED]` tag or when the player examines the body), `TESTIMONY` (a partial witness or the last person who spoke with the victim) and `ALIBI` (someone confirms a fully innocent suspect). Each NPC's prompt gets its statements from code (`linkPromptLines`) with a `[STATEMENT_GIVEN]` tag; a forgotten tag is caught from names and keywords in the reply. The body pressures the unwitting helper (`evidenceImpact`); the last-conversation testimony frightens nobody (raising only the culprit's fear would let the fear indicator name them). Evidence from the crime scene (trace, body) is photographed with the case's own crime scene picture.
